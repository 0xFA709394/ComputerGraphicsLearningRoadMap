# 20 · DRS 动态分辨率缩放（帧时间反馈回路 + 滞回分档 + 可注入控制器）

docs/27 案例 C 的最后一个缺口骨架，对应 docs/07 §8.3 动态画质。**空格键切换合成 ALU 负载**（900 次 sqrt/像素），观察 stdout 档位变化与右下角色块（红=0.5 档，绿=1.0 档）；细条纹在低档下放大软化 = DRS 的视觉代价。

## 运行

```bash
./build.sh
./drs      # 空格: 合成负载
```

## 本例要点

| 知识点 | 位置 |
|---|---|
| **帧时间反馈回路**：EMA 平滑(0.9/0.1) → 与预算比较 → 档位决策 | `DRSController.update` |
| **滞回升降档**：超载立即降、轻载需持续 25 帧才升——防抖动的关键 | 同上 |
| **控制器可注入**：`injectFrameMs` 送合成帧时间 → 纯逻辑可单测（本仓库方法论） | 同上 |
| 分档 RT 池（6 档 × 颜色/深度，档间免重建） | `lowResTarget` |
| 合成 GPU 负载（片元 ALU 循环，空格开关）——性能实验不需要真重场景 | `frag` |
| bilinear 放大占位 → **MetalFX 时间超分是 drop-in**（读低分辨率颜色+深度+运动矢量） | `upFrag` |

**headless 验证（控制器单测）**：33ms 载荷 5 步降至 0.5；5ms 载荷滞回升满 1.0；交替 40/2ms 抖动输入下仅 5 次换档、终值稳定——**无震荡即滞回的意义**。

## 开发实录踩坑

验证脚本生成 Swift 单测时用嵌套 heredoc（外层 `<<'EOF'` 内层 `<<'SWIFT'`），给内层补 `import Foundation` 的 sed 因引号差异（`<<SWIFT` 匹配不上 `<<'SWIFT'`）**静默失败**，`exit`/`String(format:)` 找不到符号。教训：**生成代码的脚本也要断言生成物**；heredoc 定界符的引号差异是 shell 元坑。

## v2 · 热降级三档（练习 3 落地，案例 C 深水区）

控制器升级为**热感知**：`setThermal(level)`（0 正常 / 1 轻 / 2 重）——热态**上调预算收紧**（重热 ×0.8）同时**压 scale 上限**（1.0→0.85→0.7）。真机每 60 帧读 `ProcessInfo.thermalState` 映射；headless 直接注入等级。

**单测四断言全过**：基线 1.0 ✓ / 热压到 0.7 ✓ / 热态轻载不越限 ✓（200 帧轻载也爬不回 1.0）/ 热解除恢复 1.0 ✓。这是"帧率-画质-功耗三角"（docs/07 §8.3）里功耗角的实现。

## v3 · MetalFX 接入点（案例 C 第 3~4 周的真机落点）

`main.swift` 内嵌**逐行接入骨架**（注释态，真机 `-DFX_ENABLE_METALFX` 一键激活）：MTLFXTemporalScaler 的三输入（低分辨率颜色/深度/运动向量）与 13 号 TAA 的速度 pass 直接复用；特性检测（apple7+）；随 DRS 档位重建的尺寸参数；**TAA 与 MetalFX 二选一**的架构纪律（双重时序累积 = 双重模糊）。

本机无 MetalFX 授权验证 → 交付即"drop-in 点精确到行 + 降级路径已验证"（bilinear 占位全绿），真机编译即活。

## 练习路线（对照 docs/27 案例 C）
