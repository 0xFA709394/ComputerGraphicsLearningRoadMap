## 题 1 · MOBA 手游：500 动态光源的移动管线

**需求澄清**：目标机 iPhone 11 起 60fps；光源多为小型点光（技能/火把）；场景中景为主，视野内同时活跃光源 ~80。

**预算**：GPU 总预算 8.3ms（120Hz ProMotion 机型）/16.6ms 基线；光照 pass ≤2ms；光源数据 500×48B≈24KB 常驻。

**架构**：Forward+（clustered 前向）。
- compute 前置 pass：把视锥切成 16×9×24 的 3D 簇网格（指数深度分布），每簇构建光源索引列表（scan+原子，07 章模式库）。
- 物体着色：每片元按视深定位簇，循环簇内列表（均值 3~6 盏）。

**选型理由**：TBDR 上 GBuffer 延迟要 imageblock 化（工程门槛高）；Forward+ 免 GBuffer、MSAA 友好、光照数与片元解耦——移动端正解。解析大光（灯笼）：top-N 用 LTC 面光，其余点光近似。

**风险与降级**：低端机降簇分辨率（视深 24→16 层）；光源总数限制 draw 端 culling（屏幕外不进列表）；光源数据双缓冲防改写撕裂。

**度量**：簇构建 pass 耗时（<0.3ms）；光照循环 ALU 占用；中端机功耗曲线（ProMotion 降频策略联动）。

## 题 2 · 开放世界白天阴影系统

**需求澄清**：10km² 地图，昼夜循环，室内外混合，角色/载具特写。

**预算**：阴影总预算 ≤3.5ms（GPU）+ 显存 ≤40MB。

**架构**：分层混合——
1. **CSM**（4 级，覆盖 0~300m）：λ=0.9 实用切分；texel snapping 稳定化；级间 blend 12.5% 过渡带。
2. **远场**：静态物体离线烘焙 distance field shadow（世界 SDF raymarch 几步）或超远 CSM 级（512 阴影图）。
3. **室内**：光照图自带烘焙阴影 + 探针。
4. **动态角色**：胶囊体 AO 阴影（贴地软阴影，接触处 PCSS 级联覆盖不到的补强）。
5. **特写**：近距物体（<10m）RT 阴影可选（高端机才开，1spp+SVGF）。

**选型理由**：单一 CSM 拉到 10km 必然精度崩（texel 世界尺寸=范围/分辨率）；分层各管一段是带宽与精度的帕累托最优。

**风险**：级联边界 popping（blend 带够宽+时序抖动掩盖）；昼夜切换时太阳-月亮双级联的淡入淡出；室内外检测（体积标记/portal）决定是否叠加远场。

**度量**：各级 texel 世界尺寸表（近级应 <5cm）；阴影 pass ms；PCF 采样次数峰值；玩家高速移动时的稳定性录屏测试。

## 题 3 · 半透明系统：植被+粒子+玻璃+水面

**需求澄清**：3A 手游画质目标；植被 10w+ 片元、粒子峰值 5w、玻璃折射、大面积水面。

**预算**：overdraw 总量 ≤4×全屏（TBDR 带宽红线）；半透明 ≤2.5ms。

**架构分层**：
1. **不透明优先**：植被 alpha-test + TAA 转子盘抗锯齿（免 blend 进 early-z）。
2. **粒子**：加色/预乘混合（免排序）为主；少数 alpha 混合粒子 GPU 深度分桶排序（bitonic，07 章）；半分辨率粒子层+上采样。
3. **玻璃**：抓屏折射（前一帧 scene color，一拍延迟用重投影补偿）；Raster Order Group 做正确混合（Apple 独家优势）。
4. **水面**：不透明深度写入的水面网格（波浪位移）+ 抓屏折射 + SSR 反射 + 深度泡沫（11 章 §5.1）。

**风险**：alpha-test 的 quad 利用率（注意片元大小 vs 纹理 mip 预算）；抓屏一拍延迟在相机快速转动时可见（velocity 加权混合缓解）；水面与粒子叠加的超频段。

**度量**：overdraw 视图逐区域截图归档；每类物体的每像素成本（counters 分桶）；半透明开启前后功耗差。

## 题 4 · 10km² 开放世界流式渲染

**需求澄清**：总资产 8GB，内存预算 2.5GB（几何+纹理），玩家载具移动（快速视点变化）。

**架构**：
- **分块（chunk）**：世界按 256m 六边形/方形网格分块；每块含网格 LOD 链+纹理+ impostor。依赖图（块的邻居预加载）。
- **LOD**：近处 meshlet 全量（GPU 剔除）→ 中距合并网格 → 远距 impostor（billboard 立方图）。
- **GPU-driven**：可见块列表 compute 剔除（hi-Z）→ indirect draw（11 章扩展篇 E 数据流）。
- **加载**：异步 IO 队列+优先级（视线方向加权）；纹理按 mip 分层加载（近 mip 先行）；瞬时限额（每帧 <8MB 上传防尖峰）。
- **虚拟纹理**：地形 mega texture 按需换页（Metal sparse）。

**风险**：快速移动时 LOD pop（几何 morph+时序淡入）；IO 尖峰与帧节奏冲突（上传预算化）；内存碎片（块级池化分配）。

**度量**：滞留率（已加载/实际可见）；每帧上传字节；块切换延迟分布（P99<200ms）；显存水位曲线。

## 题 5 · 游戏内 UI 渲染器（自绘）

**需求澄清**：主机/手游跨档；图文混排+九宫格+动效；输入延迟敏感。

**架构**：
- **图集与合批**：全部静态素材入两张 2048² 图集（图元/文字分集）；按（图集, PSO, 混合态）键排序合批，目标 <10 draw。
- **文字**：CPU 光栅化 glyph 入 LRU 图集（15 章 §6）；大字号动态缩放走 SDF 字体；shaping 用系统 CoreText/HarfBuzz。
- **裁剪**：scissor 栈（矩形裁剪为主，模板裁剪降级路径给圆角/任意形状）。
- **渲染层**：不透明背景层（early-z）→ 混合层（严格 back-to-front）→ 全屏效果（安全区/暗角）。
- **动画**：UI 变换走统一 timeline（GPU 实例化一次画全列表，CPU 只写矩阵环）。

**风险**：图集切换打断合批（LRU 策略+冷热分集）；文字缓存抖动（字号分桶+上界）；模板裁剪的带宽（监控使用率，引导美术用矩形近似）。

**度量**：draw 数、三角形数（峰值 <50k）、图集命中率（>99%）、输入采样到上屏延迟（<2 帧）。

## 题 6 · AR 真实感混合渲染管线（Apple 平台）

**需求澄清**：iOS LiDAR 机型；虚拟物体需"落地"——被真实物体遮挡、投真实阴影、光照匹配环境。

**架构**：
- **光照估计**：ARKit `ARLightEstimate`（方向+强度+色温）驱动主光；环境探针（`AREnvironmentProbe`）给 IBL——虚拟物体用 03 章全套 PBR。
- **遮挡**：ARKit 场景深度（people/body occlusion 或 LiDAR depth）写入深度前置 pass，虚拟物体 z-test 自然被真实物体遮挡。
- **阴影**：raymarch ARKit 场景重建网格（sceneReconstruction mesh）的深度图做 shadow map——虚拟物体在真实桌面投影。
- **合成**：相机帧作为背景纹理（YCbCr→RGB 转换 shader，注意色彩空间与相机白平衡）；Metal 层输出 EDR 直通，相机曝光变化时虚拟物体曝光跟随（lightEstimate 的曝光系数统一乘）。
- **物理**：重建网格转碰撞体，虚拟物体真"放"在桌上（14 章）。

**风险**：相机帧与渲染帧的时间错位（ARKit 提供锚定变换补偿）；重建网格质量差处的阴影噪点（法线平滑+深度偏置）；低光环境光估计不稳（探针 fallback 到预设 HDRI）。

**度量**：虚拟/真实交界处的遮挡边缘稳定性（录屏逐帧）；光照匹配的色差 ΔE；整机功耗（AR 全栈是耗电大户，热状态联动降级画质）。
